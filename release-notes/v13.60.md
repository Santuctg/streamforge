StreamForge v13.60 — Node panel permission audit

- Full Node panel permission audit. Panel roles are authorised live by the Main Server and decoded against Main's permission catalog, so three legacy permission strings could never match any role except Super-Admin:
  - `logs.manage` → `logs.clear` — the channel error Clear button, the stream-log clear endpoint and the Node Logs page clear button were invisible/403 for every restricted role.
  - `stream_users.kill` → `sessions.kill` — killing a viewer session from the Node Live Sessions page (UI and API) was 403 for every restricted role.
  - `categories.manage` → `categories.reorder` / `categories.edit` / `categories.delete` — reordering, renaming and deleting Node-local categories were 403 for every restricted role; each action now maps to its Main catalog permission.
- Aligned two Node actions that were weaker than their Main counterparts:
  - Channel Info (ffprobe/details page) now requires `channels.info` like the Main Info screen, and the Info button only renders for users who can open it.
  - The HLS preview (the "H" action) now requires `channels.playback` like Main's direct HTTP playback, and the dashboard button is gated the same way.
- Added `scripts/test_node_permission_audit.py`, which fails any Node Agent that references a permission outside the Main catalog or reintroduces the legacy strings. The v13.60 updater and release round-trip enforce the same contract.
- The v13.54-v13.59 fixes are carried unchanged.

```bash
sudo streamforge-update --force /root/streamforge-13.60.zip
```
