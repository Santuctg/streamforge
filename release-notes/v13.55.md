StreamForge v13.55 — Node Web Player watch route wiring fix

- Fixed the v13.53 Node Web Player regression that broke every channel: the new watch-device-CSS helper was wedged between the `/web-player/watch/{channel_key}` route decorator and `node_web_player_watch`, so FastAPI bound the route to the helper and every channel click returned the CSS text instead of the player page. The helper now sits above the decorator and the route binds to the real player handler.
- Added a source-level route-wiring guard to the release contracts, the theme tests and the staged installer: any `@app`/`@router` decorator not bound directly to a handler now fails the package before install.
- The v13.54 fixes are carried unchanged: the Main Web Player loads self-hosted HLS.js from the Nginx `/static/` cache at host root, and light themes force `color-scheme:light` on selects so native dropdown option lists open light on Main and Node.
- Remote Nodes receive the fixed Node Agent from Main automatically.

```bash
sudo streamforge-update --force /root/streamforge-13.55.zip
```
