StreamForge v13.16 — Node WebPlayer duplicate stream_id playback fix

- Root cause: an M3U can repeat the same upstream stream_id on two channels
  (production evidence: "t" (sf-144-t) and "Sony Ten Cricket"
  (sf-76-sony-ten-cricket) both carried stream_id 185). The WebPlayer media
  URL repeated the numeric stream_id and the later duplicate overwrote the
  session grant's channel map, so one channel resolved to the other and its
  live playlist failed with 403 "Playback path mismatch" while /node-play/
  key-based playback and the Main server kept working.
- WebPlayer media URLs now carry the unique channel key, which already fits
  the Nginx sf_channel_ref character class.
- Session grants mark their stream_id aliases first-claim (setdefault), so a
  duplicate can no longer steal another channel's map entry.
- Playback key resolution prefers an exact key match before any stream_id
  alias for older session grants.

Updating: install this release on the Main server first, then update the
Node Agent (Node Updates over SSH or scripts/install_node_agent.sh). The
WebPlayer watch page is served by the Node Agent, so the stream fix only
appears after the Node Agent runs v13.16.

```bash
sudo streamforge-update --force /root/streamforge-13.16.zip
```
