# StreamForge v12.56 — Browser Playback Compatibility

v12.56 fixes Web Player channels that can work in Firefox but fail or stall in Chrome when Chromium reports native HLS support as `"maybe"` and StreamForge selects that native path before HLS.js.

## Changes

- Main and Remote Node Web Players now prefer HLS.js/MSE whenever HLS.js is supported.
- Native HLS remains available as the fallback for browsers such as Safari/iOS when HLS.js/MSE is unavailable or unsupported.
- The self-hosted HLS.js copy remains first, followed by the existing CDN fallbacks.
- Existing autoplay handling, channel switching, buffering, non-destructive stall recovery, and persistent reconnect behavior are preserved.
- No FFmpeg/transcode/codec policy change is included in this release.
- Main and bundled Node Agent are aligned at `12.56`.
- The updater is bounded to the Main player template, bundled Node player runtime, version metadata, and v12.56 helper scripts; it does not restart the Main channel supervisor or reload Nginx.
- Rollback restores both player files and both VERSION files if a post-write validation fails.

## Deployment

Update Main first:

```bash
streamforge-update --force /root/streamforge-12.56.zip
```

Verify Main `12.56` and bundled Node Agent `12.56`, then push the Node update from the Main panel. No separate Node ZIP is required.
