# StreamForge v12.83 — Real client identity, verified Node TLS, signing-key hard fail

## What changed

Batch 2B of the hardening review closes the trust boundaries that identify a
viewer and that protect the Panel↔Node control channel.

- **Client identity is now the rightmost forwarded hop.** Several helpers read
  the *leftmost* `X-Forwarded-For` entry — the one any client writes before
  Nginx. `load_balancer.client_ip()` trusted it unconditionally, so any viewer
  could pick any source IP with one forged header: pass an IP allowlist,
  walk around per-IP login limits, inflate or deflate viewer counts.
  Access-policy checks and the viewer/session trackers trusted it whenever the
  peer "looked local", which Uvicorn's proxy-header rewrite made always true.
  Every consumer now shares `app/client_ip.py`, which takes the **rightmost**
  hop — the one local Nginx appends from the real socket — and only when the
  backend is bound to loopback (a bind address Uvicorn cannot rewrite).
- **Nginx resolves the real address at the proxy.** `deploy/nginx.conf` gains a
  `real_ip` block trusting loopback only, so a viewer connecting directly can
  never move `$remote_addr` with a forged chain. If a CDN or an internal proxy
  sits in front of StreamForge Nginx, add exactly that proxy's ranges to
  `set_real_ip_from` (never `0.0.0.0/0`); the update patches the installed
  site the same way, tests it with `nginx -t` and reloads it.
- **Remote Node TLS is always verified (breaking).** The per-node
  "Verify HTTPS certificate" option is removed: HTTPS to a Node now always
  uses a verifying SSL context, so node API traffic cannot be intercepted by
  anyone on the path. **Nodes reached over HTTPS with a self-signed or
  name-mismatched certificate must be given a trusted certificate (or reached
  over `http://`) before updating** — otherwise their management calls fail
  with a certificate error. The database column is left in place but ignored.
- **A weak signing key refuses to start (v12.82's promised follow-up).**
  `STREAMFORGE_SECRET_KEY` empty, the published development default or shorter
  than 32 characters now stops startup with the exact fix in the message,
  instead of only logging an error. The updater repairs a weak or missing key
  in `/etc/streamforge.env` (fresh 64-hex value, original file backed up)
  before the workers restart, so upgraded servers never hit the refusal;
  fresh installs have always generated a strong key.
- The v12.82 patch round-trip and updater regression test now read their
  fixtures from the release tags, so later branches keep proving the
  historical release instead of failing against newer sources.

## Installation

Requires installed Main v12.82 (or v12.83 for a safe reinstall). Update older
servers in order. Download and SHA256-check the official release ZIP, then
run:

```bash
streamforge-update --force /root/streamforge-12.83.zip
```

The updater patches the Main sources in place from exact-text hunks
(`scripts/apply_v1283_hardening.json`, 11 files) and copies the new
`app/client_ip.py` module: every anchor is verified in a staged copy first,
and an unexpected tree refuses the update with nothing written. It then
repairs a weak `STREAMFORGE_SECRET_KEY`, applies the real_ip block to
`/etc/nginx/sites-available/streamforge` (guarded by `nginx -t`, then a
graceful reload) and restarts `streamforge` and `streamforge-public` so the
new code is live at once; the channel supervisor and live streams keep
running. Backup goes to `/var/backups/streamforge/v1283-<timestamp>/`
(including the env file and Nginx site), and a failure after the write rolls
every file back and restores both services. The bundled Node Agent is
byte-identical to v12.82 — **Remote Nodes do not need an update for this
release.**

## After updating

1. `curl -fsS http://127.0.0.1:8800/version` must answer `12.83`.
2. If any Remote Node is reached by HTTPS with a self-signed certificate,
   install a trusted certificate for it (or switch its URLs to `http://`)
   before its next status check.
3. Behind a CDN or internal proxy? Add its ranges to `set_real_ip_from` in
   `/etc/nginx/sites-available/streamforge` and run
   `sudo nginx -t && sudo systemctl reload nginx`.
