# StreamForge v12.76 — Security hardening

Six security improvements for the Main Server. Live streams keep running
during the update: only the Main HTTP workers restart.

## What changed

1. **Stream and relay keys no longer depend on `STREAMFORGE_SECRET_KEY`.**
   Viewer stream links and the relay keys Remote Nodes use to pull channels
   are now derived from a secret stored in the database. Main seeds it once
   from the current secret key, so **every existing link and relay key stays
   exactly the same** after updating. Rotating `STREAMFORGE_SECRET_KEY` later
   no longer stops Remote Node channels or breaks playlist links. The secret
   travels with database backups. The root Nginx relay helper reads the same
   secret.

2. **Encrypted backups for destinations.** Set a **backup passphrase** under
   **Backups → Backup encryption** (12+ characters). Every archive sent to a
   backup destination (local folder, SMB, SSH, Google Drive) is then encrypted
   with AES-256-GCM (key derived from the passphrase with scrypt). Main's own
   retained copies stay usable on this server. Restoring an encrypted backup
   uses the saved passphrase, or the passphrase typed in the restore form —
   for example on a new server. Offline decryption:
   `python3 /opt/streamforge/app/backup_crypto.py decrypt IN.tar.gz OUT.tar.gz`.
   **Store the passphrase safely; without it encrypted backups cannot be
   restored.** Until a passphrase is set, destinations keep receiving
   unencrypted archives and the Backups page shows a warning.

3. **SSH host keys are pinned.** Node install/administration/uninstall and
   SSH backup destinations remember each server's SSH host key on first
   contact (`/var/lib/streamforge/.ssh/known_hosts`) and refuse a different
   key afterwards, instead of accepting any key. If a server was really
   reinstalled, the error message shows the `ssh-keygen -R` command to forget
   the old key.

4. **Security headers.** All Main responses send
   `X-Content-Type-Options: nosniff` and
   `Referrer-Policy: strict-origin-when-cross-origin`. Panel pages also send
   `X-Frame-Options: SAMEORIGIN` and
   `Content-Security-Policy: frame-ancestors 'self'; base-uri 'self'; object-src 'none'`
   against clickjacking. Playlist and Web Player routes stay embeddable.
   HSTS is opt-in (`STREAMFORGE_HSTS_MAX_AGE=<seconds>` in
   `/etc/streamforge.env`) because it would force HTTPS on every port of the
   host, breaking a plain-HTTP Playlist/Web Player on the same domain.

5. **Changing a password ends that user's other sessions.** The session
   cookie now carries a fingerprint of the password. After a password change
   or reset, every other browser of that Panel user is signed out; the browser
   that changed its own password stays signed in. Sessions from before the
   update are kept (they adopt the current password).

6. **Xtream login limits.** `/get.php`, `/player_api.php`,
   `/live/<user>/<pass>/…` and Web Player logins now count failures per source
   IP: 10 failures for one username in 10 minutes block that IP + username for
   15 minutes; 100 failures across usernames block the IP for 15 minutes.
   Refused attempts while blocked are not counted, so one app with a wrong
   saved password cannot block everyone behind the same carrier-grade NAT.
   If the limiter itself fails, logins are allowed (fail-open).

No Node Agent, Nginx configuration, channel supervisor or FFmpeg changes.

## Installation

Requires installed Main/bundled Node v12.75 (or v12.76 for a safe reinstall).
Update older servers to v12.75 first. Download and SHA256-check the official
release ZIP, then run:

```bash
streamforge-update --force /root/streamforge-12.76.zip
```

The scoped updater copies the installed files to a staging directory, applies
`scripts/apply_v1276_security.py` (exact-text hunks; it refuses if any anchor
is missing), adds `app/stream_keys.py`, `app/xtream_guard.py` and
`app/backup_crypto.py`, verifies markers and Python syntax, backs everything up
to `/var/backups/streamforge/v1276-<timestamp>/`, and installs atomically —
including the root helper `/usr/local/sbin/streamforge-apply-main-access`.
Every Node runtime file is verified byte-for-byte unchanged. Backup,
reinstall, anchor refusal and controlled rollback are regression-tested. Only
`streamforge` and `streamforge-public` restart.

After updating: open **Backups** and set a backup passphrase.

Running Remote Nodes have no code changes in this release; updating them via
**Node Updates** only aligns their displayed version.
