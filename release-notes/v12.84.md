# StreamForge v12.84 — Role Manager and documentation fixes

## What changed

- **Settings/Backups-only operators can log in to their allowed page.** The
  login landing-page list previously omitted both pages and sent these roles
  to `/no-access`, despite their permissions being valid.
- **Role mutations are audited.** Successful create/edit/delete actions record
  the actor and role identity; edits include granted/revoked permission keys
  and the previous name. Refused changes do not record a success event.
  Existing permission ceilings, Super Admin protections, own-role locks and
  assigned-role deletion guards remain in place.
- **Vault permission labels match actual behavior.** The historical
  `panel_users.password_vault_manage` flag is explicitly labelled legacy: it
  does not enable/disable automatic encrypted saving when the vault is active.
  Password reveal is still separately authorized, reauthenticated and audited.
  No credentials are migrated or exposed by this release.
- **Operator documentation corrected:** current download/install examples,
  full rollback requirements, v12.83 TLS and proxy trust instructions,
  signing-key repair limits, current tests and role permission names.

## Upgrade

Requires installed Main **v12.83**, or v12.84 for a safe reinstall. Older
servers must update in order. Download the official ZIP and verify its SHA256
against the GitHub release asset digest before running:

```bash
streamforge-update --force /root/streamforge-12.84.zip
```

The updater stages `app/main.py` and `app/permissions.py`, applies
`scripts/apply_role_manager_fix.py`, verifies Python syntax and only then
backs up and installs the changes. Unexpected/missing/ambiguous anchors refuse
the update before any installed file changes. Both VERSION files become
12.84. The bundled `node_agent/app.py` is restored only if it differs from the
pinned, unchanged v12.83 payload. File modes and ownership are preserved.

Backups are stored under `/var/backups/streamforge/v1284-<timestamp>-<suffix>/`.
Write or worker-restart failures trigger rollback of every touched file.
Only `streamforge` and `streamforge-public` restart; Nginx, the channel
supervisor, environment files and database schema are untouched.
**Remote Nodes need no update for v12.84.**

This release does not add Newcamd/descrambling or ship the experimental UDP
diagnostic files. It does not change v12.83's certificate verification rules.

## Verify

```bash
curl -fsS http://127.0.0.1:8800/version
systemctl is-active streamforge streamforge-public streamforge-channel-supervisor nginx
```

Expect version `12.84` and four active services. Test Settings/Backups-only
operator logins, and check **Logs** for role mutation events after a test
role create/edit/delete. Do not grant backup access merely to test login:
backup download/restore permissions are sensitive.
