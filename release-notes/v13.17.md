StreamForge v13.17 — GitHub release feed rate-limit hardening

- Root cause: scheduled Main updates failed with "HTTP Error 403: rate limit
  exceeded" because the root updater and the web Updates page use anonymous
  api.github.com requests, which GitHub caps at 60 per hour per server IP.
- Release planning now needs only ONE GitHub API request for sequential
  minor updates: the helper fetches /releases/tags/{target} directly.
- Optional STREAMFORGE_GITHUB_TOKEN (or GITHUB_TOKEN) adds Bearer auth for
  a 5000 requests/hour limit. Set it in /etc/streamforge.env and restart
  streamforge / streamforge-public after an update.
- The web release feed caches the latest release for 5 minutes (was 60s)
  and falls back to the cached result when GitHub answers 403/429.
- Rate-limit failures now explain the quota reset and the token option
  instead of a bare "HTTP Error 403".
- Main-only release: the privileged system-control helper is refreshed, the
  Node Agent runtime bytes are unchanged and Remote Nodes need no update.

```bash
sudo streamforge-update --force /root/streamforge-13.17.zip
```
