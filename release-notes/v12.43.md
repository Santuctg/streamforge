# StreamForge v12.43

## Permanent updater hotfix for v12.42 dead-input schema

- Fixes the v12.42 update failure: `StreamForge Main install verification FAILED - missing DB columns in channels: dead_input_recovery_interval`.
- Root cause: the v12.42 application included the additive `dead_input_recovery_interval` schema migration, but the inherited modern updater path reached `verify_main_install.py` before that runtime migration was executed on the live database.
- v12.43 patches the staged inherited updater so the additive SQLite migration runs immediately before Main install verification, inside the updater's existing backup/rollback boundary.
- The migration is idempotent: if `channels.dead_input_recovery_interval` already exists, it is left unchanged; otherwise it is added as `INTEGER NOT NULL DEFAULT 30`.
- Existing v12.42 dead-input recovery behavior is retained: per-channel configurable recovery interval, 30-minute default, quick failover before full-cycle exhaustion, and reset to primary input for the next recovery cycle.
- Added a regression guard that requires the migration injection to remain before Main install verification in future release bridges.

## Update instructions

Download or rename the GitHub release source archive to `streamforge-12.43.zip`, then run:

```bash
streamforge-update --force /root/streamforge-12.43.zip
```

After Main update:

```bash
cat /opt/streamforge/VERSION
sqlite3 -header -column /var/lib/streamforge/streamforge.db "SELECT name,type,[notnull],dflt_value FROM pragma_table_info('channels') WHERE name='dead_input_recovery_interval';"
```

Expected version:

```text
12.43
```

Expected schema default:

```text
dead_input_recovery_interval  INTEGER  1  30
```
