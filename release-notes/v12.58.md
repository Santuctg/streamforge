# StreamForge v12.58 — Node Update Center Cleanup

v12.58 keeps all Remote Node update controls inside the dedicated **Node Updates** page and removes the legacy page-navigation leak from the v12.57 Advanced action.

## Changes

- Changes each row's `Advanced` action into an inline expand/collapse panel on **Node Updates**.
- Keeps the normal per-Node API update and SSH recovery / port-migration controls on the same page.
- Removes invalid nested-form structure by separating the bulk selection form from the per-Node API/SSH forms.
- Redirects legacy `/nodes/{node_id}/update` GET requests back to the unified Node Updates center and automatically opens the matching Node row.
- Returns individual API/SSH update success and error redirects to the unified Node Updates center instead of the old standalone page.
- Adds `current_version` to the live update-status response so the table refreshes the installed Node version after an update without a manual page reload.
- Preserves v12.57 bulk behavior: every selected Node starts immediately in parallel, an already-running Node is not duplicated, and one Node failure does not stop the others.
- Aligns Main and bundled Node Agent metadata at `12.58` while keeping the Node runtime payload byte-identical to v12.57.
- The Main updater restarts only `streamforge` and `streamforge-public`; it does not restart `streamforge-channel-supervisor` or reload/restart Nginx.
- No separate Node ZIP is required.

## Deployment

Update Main first:

```bash
streamforge-update --force /root/streamforge-12.58.zip
```

Verify Main and bundled Node Agent are `12.58`. Then open **Node Updates**. `Advanced` should expand inline, and bulk updates remain available through `Select All` / `Update Selected`.
