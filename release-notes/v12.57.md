# StreamForge v12.57 — Node Bulk Update Center

v12.57 moves Remote Node updates out of individual Node cards into one dedicated bulk update center.

## Changes

- Removes the per-Node `Update` button from the Nodes page.
- Adds a permission-aware `Node Updates` sidebar entry using the existing `nodes.update` permission.
- Lists Remote Nodes with checkbox selection, current version, target version, update state, progress, and per-Node errors.
- Adds `Select All`, selected count, and `Update Selected` controls.
- Starts **all selected Node API updates immediately in parallel**. There is no global two-Node limit or batch queue.
- Reuses the existing isolated per-Node update worker and `/nodes/{node_id}/update/status` live-status endpoint.
- A Node that is already updating is not started a second time, and a failure on one Node does not stop the other selected Nodes.
- Keeps the existing individual update / SSH migration page available through `Advanced`.
- Aligns Main and bundled Node Agent metadata at `12.57` while keeping the Node runtime payload unchanged from v12.56; the Main updater verifies byte parity before relabeling it.
- The Main updater restarts only `streamforge` and `streamforge-public`; it does not restart the Main channel supervisor or reload/restart Nginx.
- No separate Node ZIP is required.

## Deployment

Update Main first:

```bash
streamforge-update --force /root/streamforge-12.57.zip
```

Verify Main `12.57` and bundled Node Agent `12.57`, then open **Node Updates**, select the desired Remote Nodes (or Select All), and click **Update Selected**. All selected Node updates start at the same time.
