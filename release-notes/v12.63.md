# StreamForge v12.63 — Encrypted Panel User Saved Password Vault

## What's new

- **Show saved password** is available **only to Super Admin** on Main **Panel users** (desktop/mobile).
- Requires re-entering the currently signed-in Super Admin's password for **each** reveal; confirmation is never stored. No standalone reveal page or GET URL.
- Revealed plaintext appears only after successful re-auth, for up to **10 seconds**, then is removed from the UI. Switching tabs or leaving the page removes it sooner. HTTPS is required in deployment.
- Main stores the usual **one-way scrypt hash** for login, plus a separate **Fernet-encrypted** vault copy only for passwords set **after installing v12.63**. Current hash-only users are marked **No saved password — reset first**.
- The encrypted copy is updated upon Main Panel user create, Main Panel admin reset, Main self-password change, and Remote Node self-password change. It is **not sent to Remote Nodes**.
- Failed admin confirmation is rejected and rate-limited; reveals and failures are audited **without recording the password**. Cross-site reveal attempts are blocked, and reveal responses use `Cache-Control: no-store`.
- The v12.62 **Change password** link fix (query-based hidden-panel routing) is included. Existing v12.61 Password/Confirm Show/Hide UI remains available.

## Important security conditions

**This feature intentionally makes future passwords recoverable and increases risk versus hash-only storage.**

- A **stable, securely generated 32+-character `STREAMFORGE_SECRET_KEY`** must be configured to the **same value in both `streamforge` and `streamforge-public` services**. The built-in development default is explicitly rejected by the vault. Do not paste or log the key.
- Vault ciphertext is derived from the Main secret with purpose separation; **changing or losing that secret prevents decryption**. Back up and protect both the database and the secret independently.
- Anyone compromising both the Main application and secret can potentially decrypt saved passwords. Restrict server access, protect backups, require HTTPS, and do not expose the reveal API to unauthenticated networks.
- Although plaintext is cleared from the UI after ten seconds, an authorized viewer and browser developer tools can still capture it. Avoid viewing credentials on shared/untrusted devices.
- Historical passwords cannot be recovered; reset each account first.

## Installation boundary

- Main and bundled Node metadata set to **12.63**. **No separate Node ZIP**; Node runtime files are byte-identical to v12.62 and v12.61. The bounded updater supports **direct Main upgrade from v12.61** without an intermediate v12.62 installation.
- Additive nullable DB column `admin_users.password_vault_enc`; old authentication hashes are retained. Schema migration happens during normal Main startup. Downgrading leaves the harmless extra column; there is no migration that deletes credentials.
- Bounded updater copies Main `app/main.py`, `app/models.py`, `app/db.py`, `app/panel_password_vault.py`, `app/templates/admin_users.html`, `app/templates/admin_user_form.html`, and VERSION metadata; it backs up and rolls back changed files.
- Restart only `streamforge` and `streamforge-public`. **Do not restart channel supervisor or Nginx**.
- No production deployment should begin until the secret-strength prerequisite and full CI pass.

After release ZIP is published, verify SHA256 before running:

```bash
streamforge-update --force /root/streamforge-12.63.zip
```

Hard refresh, then choose **Panel users → Show saved password**. Accounts with old passwords must be reset once; a correct Super Admin re-authentication is required for each reveal.
