# StreamForge v12.63 — Protected Saved Password Vault and Login Attempt Security

## Saved Panel User passwords
- Adds **Show saved** to the Panel users list, visible only to an active Super Admin after successful fresh password re-verification.
- Each reveal is an authenticated, CSRF-protected POST, rate-limited, permission-checked and logged without the recovered password.
- Browser holds the recovered password for **10 seconds** and clears it when hidden, closed or tabbed away. No password is rendered into HTML at page load.
- New Panel User creations, administrator password resets, own password updates and updates from a Remote Node save an **AES-256-GCM encrypted copy**, in addition to the existing one-way scrypt login hash.
- Passwords saved **before** v12.63 have no recoverable copy. **Change password once** to enable Show saved; prior hashes cannot be reversed. Accounts keep working as before.
- The independent encryption key is stored at `/etc/streamforge-panel-vault.key`, root-owned, streamforge-group readable only. The updater creates the key once and **never replaces it**. Back up this key securely, separately from the StreamForge database; losing the key makes saved passwords unrecoverable, while login hashes remain functional.
- This feature deliberately increases the impact of a Main server/key compromise, compared with nonrecoverable passwords. Restrict server and backup access and use TLS for the Main Panel.

## Login and application hardening
- Limits failed Main Panel and Remote Node live-auth logins using a persistent, parameterized SQLite guard separate from the StreamForge data database.
- Limits attempts per client-IP+username to **5 per 15 minutes** and per client IP to **20 per 15 minutes**, using short-lived temporary blocks.
- Keeps login errors generic, verifies unknown accounts against a dummy scrypt hash, and clears throttles after successful authentication.
- Refuses login when the attempt guard cannot be used, rather than bypassing the protection.
- Password reveal has its own rate-limit scope to inhibit Super Admin password guessing.
- New password-reveal endpoint is restricted to active Super Admins with live permission checks; CSRF token and same-origin fetch are required. No credentials are written to audit or server logs.
- Existing SQLAlchemy bound-parameter lookups and typed integer target IDs are retained. A regression test checks malicious SQL text cannot influence credential-guard storage.
- This is defense in depth, **not a claim of immunity** to every SQL injection, XSS, stolen session or server attack.

## Deployment
- Main + bundled Node metadata: `12.63`, with **no Node runtime changes**.
- Scoped updater changes the Main app security, schema, and Panel users template; includes preflight, backup, rollback and 13-file bundled Node parity guard.
- Restart Main HTTP services only; **Main channel supervisor and Nginx remain untouched**.
- A nullable `admin_users.password_vault_enc` column is added on startup; rollback does not destructively drop this column.
- Do **not** deploy while ongoing Main HTTP update jobs are active. Key and database backups must be protected separately.

After the official asset SHA256 has been confirmed:

```bash
streamforge-update --force /root/streamforge-12.63.zip
```

Hard refresh **Panel users**. Existing accounts show **Reset to enable Show**. Change one user's password, then **Show saved**, reauthenticate with the Super Admin password and inspect the credential for ten seconds. Test login throttling on a nonproduction account; do not intentionally lock out your production admin.

## Operational key backup

The key is **not** stored in the release ZIP and must not be shared via chat, logs or public GitHub. Back it up using a separate protected root-only vault location, with permissions no broader than root/service. Do not delete or regenerate the key after saving any password.
