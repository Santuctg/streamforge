# StreamForge v12.63 — Opt-in encrypted Panel User credential vault

## What changes

Panel Super Admins can now inspect **newly saved** Panel User passwords, only when the account password was created/reset with the new **Save this new password in the encrypted vault** opt-in selected.

- The ordinary login password stays in the existing one-way scrypt hash. Authentication behavior is unchanged.
- Recoverable secrets are stored in a **separate Main-only database table** using Fernet authenticated encryption and a **dedicated encryption key**. The key is never stored in the database, release, Node Agent or repository.
- No automatic import of old passwords is possible. Previously saved **hash-only** account passwords must be reset and explicitly opted in before the vault can reveal them.
- `panel_users.password_reveal` allows a Super Admin to delegate reveal to any custom role from **Roles → Edit role**, subject to that role's existing panel-user visibility/permission ceiling; revealing a built-in Super Admin password is still blocked for non-Super Admins. It requires the viewer's own current password, with a separate audit record and rate limiting.
- `panel_users.password_vault_manage` separately controls the create/reset opt-in checkbox for roles that already have `panel_users.create` or `panel_users.edit`. Reveal does not imply edit or storage permission.
- Only the built-in Super Admin can **grant or revoke** either sensitive permission. Other Admins cannot delegate these privileges even if they possess them.
- Each reveal uses a session-bound CSRF token, HTTPS-only POST, no-store response, authorized browser-only text, audit logging, durable cross-worker reveal rate limiting (five failures per fifteen minutes), and a 10-second auto-hide.
- Main and Remote Node self-service password changes, account deletion and resets without vault opt-in invalidate old stored secrets. Account deletion cascades to the vault table.
- The existing v12.62 Change password navigation fix remains intact, with v12.61 inline password entry visibility and v12.60 per-Node Advanced logs.
- Node runtime is unchanged; bundled Node VERSION is metadata-only 12.63.

## Security boundary and trade-off

Encrypted storage makes passwords **recoverable**. Anyone who compromises both the database and the key can recover them. Browser malware/extensions, a compromised Super Admin account, or a compromised server can still disclose plaintext during authorized reveal. Only operate this feature on a trusted **HTTPS** Main Panel with strict Super Admin access. Back up the key separately using encrypted secure storage; losing the key makes stored vaulted passwords unrecoverable. Do not print, paste into chats, or commit this key. Do not deploy on a public HTTP-only Panel.

## Setup (on Main only, after upgrading the Main release)

No key is auto-generated by the updater: the feature fails closed until provisioning.

1. Verify HTTPS is enabled for the Main Panel.
2. On the Main host, create the encrypted credential key file without printing the secret:

```bash
sudo install -d -m 0700 /etc/streamforge
sudo python3 - <<'PY'
import base64, os
from pathlib import Path
path=Path('/etc/streamforge/panel-password-vault.env')
if path.exists():
    raise SystemExit('Key file already exists. Preserve it; do not regenerate.')
key=base64.urlsafe_b64encode(os.urandom(32)).decode('ascii')
fd=os.open(str(path), os.O_WRONLY|os.O_CREAT|os.O_EXCL, 0o600)
try:
    os.write(fd, ('STREAMFORGE_PANEL_PASSWORD_VAULT_KEY='+key+'\n').encode('ascii'))
finally:
    os.close(fd)
print('Created root-only vault encryption key. Contents not printed.')
PY
sudo install -d -m 0755 /etc/systemd/system/streamforge.service.d
printf '[Service]\nEnvironmentFile=/etc/streamforge/panel-password-vault.env\n' \
  | sudo tee /etc/systemd/system/streamforge.service.d/panel-password-vault.conf >/dev/null
sudo systemctl daemon-reload
sudo systemctl restart streamforge
```

Only the Main Panel **streamforge** service receives the vault key. Do not configure it on Nodes. Schedule restart after active node updates have finished (Main update jobs can be in-memory).

3. Hard-refresh Panel users. A Super Admin may configure a delegated role under **Roles → Edit role → Panel Administration**, selecting **Reveal saved passwords** and/or **Save passwords in vault**. Creating or resetting a user with the vault opt-in saves a recoverable password; authorized users see **Show saved password** only for passwords already saved and within their target scope, then must enter their own current password to reveal for 10 seconds.

When key is missing/invalid, the UI displays a vault-disabled note and no credentials are saved recoverably.

## HTTPS and reveal rate-limit guard

Saved-password reveal requires a same-origin HTTPS POST with matching Origin and Host. TLS offloaded by Nginx must send a trustworthy X-Forwarded-Proto, accepted only from the direct loopback peer.

Super Admin reveal attempts use a separate persistent SQLite database at `/var/lib/streamforge/panel-vault-reveal-guard.sqlite3`. The Main service account must have write access to the parent directory. If this guard is unavailable, only saved-password reveal fails closed; existing Main and Node login remains unchanged. The guard stores attempt metadata, never passwords or encryption keys.

## Main release installation

```bash
streamforge-update --force /root/streamforge-12.63.zip
```

The bounded updater changes the Main model, adds a vault route module, stages and patches the Main app, updates two Panel User templates, and aligns Main/bundled Node metadata. It checks Node runtime byte parity, tests Main Python syntax before writes, and backs up the modified files for rollback. It restarts **streamforge** and **streamforge-public** only; it does not restart the channel supervisor or Nginx. No separate Node ZIP.
