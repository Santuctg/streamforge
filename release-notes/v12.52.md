# StreamForge v12.52

## Updater cache-hygiene hotfix

- Fixes the v12.51 Main update failure: `v11.63 package contains cache/metadata directories`.
- Root cause: the v12.51 wrapper ran `python3 -m py_compile` directly against the extracted release source before nested staging, which created `node_agent/__pycache__` inside an otherwise-clean package.
- Replaces that source-tree `py_compile` check with Python `compile()` syntax validation, which performs no bytecode or cache writes.
- Adds `STREAMFORGE_V1252_NO_SOURCE_BYTECODE` and a generic release regression guard so future current-version updaters cannot run source-tree `py_compile` before staging.
- Adds an explicit pre-staging hygiene check for `__pycache__`, Python cache directories, `*.pyc`, and `*.pyo` before the inherited full updater runs.
- Preserves the v12.51 Remote Node relay health-probe single-owner/in-flight deduplication fix.
- Preserves the v12.50 Main local-relay DB checkout fix.

## Versions

- Main: `12.52`
- Bundled Remote Node Agent: `12.52`

## Update

Do not retry the v12.51 ZIP that failed the package-hygiene guard. Download the v12.52 release and run:

```bash
streamforge-update --force /root/streamforge-12.52.zip
```

After Main verification, push the Remote Node update from the Main panel. The Main update does not automatically update Remote Nodes.
