# StreamForge v12.75 — Secure Main Panel session cookie on HTTPS

The Main Panel login session cookie never carried the `Secure` attribute,
even when the Panel was used over HTTPS, so a browser could send it over a
plain-HTTP request to the same host.

Main now marks the session cookie `Secure` whenever the request arrived over
HTTPS, decided per request from the `X-Forwarded-Proto` header the managed
Nginx already sets (the same approach the Remote Node Panel cookie uses).
Plain-HTTP access, such as IP-only installs, keeps working: there the cookie
is issued without `Secure` exactly as before. Other cookies are untouched.

After updating, existing Panel sessions stay valid; the next session update
(or a fresh login) re-issues the cookie with `Secure` on HTTPS.

No Node runtime, Nginx, Channel Supervisor, streaming, vault or login-guard
changes were introduced.

## Installation

Requires installed Main/bundled Node v12.74 (or v12.75 for a safe reinstall).
Update older servers to v12.74 first. Download and SHA256-check the official
release ZIP, then run:

```bash
streamforge-update --force /root/streamforge-12.75.zip
```

The scoped updater patches a staged copy of the installed `app/main.py` with
`scripts/apply_main_hotfixes.py` (fix 4; earlier fixes are skipped when
already present), verifies the result, then installs it atomically with
Main/Node version metadata. Every other Node runtime file is verified
byte-for-byte unchanged. Backup, reinstall and controlled rollback are
regression-tested. Only the Main HTTP services (`streamforge`,
`streamforge-public`) restart.

Running Remote Nodes have no code changes in this release; updating them via
**Node Updates** only aligns their displayed version.
