# StreamForge v12.74 — Fresh installs start again

Since v12.64, the release `app/main.py` still imported the v12.63 per-account
login guard (`login_locked`, …) that `app/panel_login_guard.py` no longer
provides. Existing servers were unaffected because each updater patched the
installed `app/main.py` in place, but a **fresh install** from the release
ZIP shipped a Main that failed at import and never started.

This release integrates those in-place Main patches (v12.64 IP login guard,
v12.65 block-origin tracking, v12.66 managed password retention, v12.68
password-reset popup CSRF context) into the release `app/main.py`. The
result is the same Main code that an updated v12.73 server already runs.
A fresh install was started and checked: login page, bad/good admin login,
dashboard, branding, backups and Panel Users pages.

No behavior changes for existing servers, and no Node runtime, Nginx,
Channel Supervisor or streaming changes.

## Installation

Requires installed Main/bundled Node v12.73 (or v12.74 for a safe reinstall).
Update older servers to v12.73 first. Download and SHA256-check the official
release ZIP, then run:

```bash
streamforge-update --force /root/streamforge-12.74.zip
```

The scoped updater verifies that the installed `app/main.py` already carries
every integrated patch (it refuses and changes nothing otherwise), verifies
the Node runtime byte-for-byte, then updates only Main/Node version metadata.
The installed `app/main.py` is never replaced. Backup, reinstall and
controlled rollback are regression-tested. Only the Main HTTP services
(`streamforge`, `streamforge-public`) restart.

Running Remote Nodes have no code changes in this release; updating them via
**Node Updates** only aligns their displayed version.
