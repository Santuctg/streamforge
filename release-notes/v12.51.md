# StreamForge v12.51

## Remote Node relay health-probe deduplication

- Fixes a confirmed Remote Node recovery-timer race that could multiply Main-relay health probes for one channel while the Main source was unavailable.
- Adds `STREAMFORGE_NODE_RELAY_HEALTH_PROBE_SINGLE_OWNER_V1251` so a recovery callback must still own the exact `restart_timer` before it can probe or mutate recovery state.
- Keeps the timer reservation in place while the HTTP manifest health request is in flight, preventing the 5-second desired-channel watchdog from scheduling another recovery for the same channel.
- Adds a per-channel relay-health probe-in-flight guard shared by the stall watchdog and recovery path so the two paths cannot probe Main concurrently.
- Rejects stale recovery timers without sending another HTTP request or clearing a newer timer reservation.
- Preserves the existing behavior: transient Main `503` remains retryable, confirmed Main recovery `409` causes the Node FFmpeg to exit, and a stopped Main channel returns `410`.
- Retains the v12.50 Main local-relay DB checkout fix (`STREAMFORGE_LOCAL_RELAY_DB_CLOSE_V1250`).

## Production evidence behind the fix

- The affected Node had one dedicated channel supervisor, not duplicate supervisor processes.
- The supervisor accumulated roughly 880+ threads during the incident.
- Main access logs showed health-probe bursts as high as 137 requests/second for one channel even though the configured recovery probe interval is 15 seconds.
- About 89% of the post-update relay `503` responses in the measured window were `StreamForge-Node-RelayHealth/11.1` requests, confirming a health-probe storm rather than an FFmpeg respawn storm.

## Versions

- Main: `12.51`
- Bundled Remote Node Agent: `12.51`

## Update sequence

1. Update Main with the v12.51 ZIP.
2. Verify Main services and the bundled Node Agent version.
3. From the Main panel, push the Node update to the Remote Node.
4. Verify the Remote Node reports v12.51 and the V1251 marker is present.

```bash
streamforge-update --force /root/streamforge-12.51.zip
```

The Main update does not automatically push the update to Remote Nodes.
