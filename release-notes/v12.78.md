# StreamForge v12.78 — Overview values and SSH Node update fix

## What changed

1. **Overview cards are complete as soon as the page opens.** Memory
   used/total, disk used/free/total and the network Download/Upload rates are
   now rendered with the page instead of showing `—` until the first live
   refresh. The first live refresh runs about one second after the page
   loads instead of five; the five-second refresh cadence is unchanged.

2. **Current values beside the chart legends.** Every Overview chart shows the
   latest value next to its legend entry: CPU and Memory usage, network Input
   and Output, Online users, Total and Online channels, and GPU usage,
   encoder, VRAM and temperature when a GPU is present. CPU, Memory, Input,
   Output and Online users follow the existing live refresh; the other values
   come from the latest history sample.

3. **Charts say when they are loading.** While the chart history is being
   fetched each chart shows "Loading…", then "No history yet" or
   "Could not load history" if there is nothing to draw.

4. **SSH Node updates no longer log `fetch_hlsjs.sh: No such file or directory`.**
   The SSH update/install package now includes `scripts/fetch_hlsjs.sh`, so the
   Node installs its local hls.js copy during the update. The error was
   harmless (the update finished and the Node fetched hls.js later), but it
   looked like a failure in the live log.

5. **Clearer SSH update confirmation.** "Reinstall and restart this Node over
   SSH?" now reads "Update this Node over SSH? The Node Agent is reinstalled
   with its current token and settings, and the Node restarts briefly."

No extra server load: the new card values come from the snapshot the page
already reads, and the legends reuse data the dashboard already fetches. The
only addition is one early metrics request per Overview page load.

## Installation

Requires installed Main/bundled Node v12.77 (or v12.78 for a safe reinstall).
Update older servers to v12.77 first. Download and SHA256-check the official
release ZIP, then run:

```bash
streamforge-update --force /root/streamforge-12.78.zip
```

The scoped updater patches staged copies of the installed files
(`app/ssh_installer.py`, `app/templates/dashboard.html`,
`app/templates/node_updates.html`, `app/templates/node_update.html`,
`app/static/app.js`, `app/static/dashboard.js`) with
`scripts/apply_v1278_dashboard.py` (exact-text hunks; refuses if any anchor is
missing), checks that the bundled Node runtime is unchanged, backs up to
`/var/backups/streamforge/v1278-<timestamp>/` and installs atomically. Backup,
reinstall and controlled rollback are regression-tested. Only `streamforge`
and `streamforge-public` restart; the channel supervisor, Nginx and live
streams keep running. Reload the Overview page afterwards.

Remote Nodes need no update for this release: the Node Agent code is
unchanged. Updating them from **Node Updates** only aligns their version
number with Main.
