# StreamForge v12.91 — Node expiry is Bangladesh time everywhere

## What changed

- **Fixed:** the expiry time you type on the Main Panel (Nodes → Edit) is now treated as **Bangladesh (BD) wall time everywhere**. Before this release a plain date entry (the form default) was read as UTC, so entering `12:12 PM` showed `6:12 PM` on the Node dashboard and the service lock fired 6 hours late.
- The Node Agent now interprets naive values from the heartbeat as **Asia/Dhaka (+06:00)**: the dashboard card shows exactly what you entered (in 12-hour BD format) and the channel lock engages at the BD moment you intended. Entries saved with an explicit UTC offset stay epoch-accurate.
- Main's Nodes list expiry badge compares BD wall time now and is labelled **Expires (BD)**; the Node form help text says BD time.
- The v12.90 enforcement behaviour is unchanged: expiry passes → channels stop, expiry extended/cleared → pre-lock channels resume automatically.
- New updater `scripts/force_update_v1291.sh`; `scripts/update.sh` repointed to it. Both VERSION files bumped to 12.91.

## Remote Nodes

**Remote Nodes must be updated from Node Updates** to get the corrected interpretation. Until then a remote node keeps the v12.90 behaviour (naive values read as UTC, 6 hours off).

## Existing data

Expiry dates saved before v12.91 were stored under the UTC interpretation. **Open Nodes → Edit and set the date again** right after updating Main.

## Upgrade

Requires installed Main **v12.90**. Older servers must update in order.

## Verify

```bash
curl -fsS http://127.0.0.1:8800/version
```

Expect `12.91`. Then:

1. Re-save the node expiry on Main (Nodes → Edit), e.g. `2026-12-02 12:12`.
2. Update the Remote Node from **Node Updates**.
3. Open the Node dashboard — the card must show **`02 Dec 2026 12:12 PM`** (not `6:12 PM`).
