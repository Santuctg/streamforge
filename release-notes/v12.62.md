# StreamForge v12.62 — Panel User Change Password Navigation Fix

Fixes **Change password** opening Dashboard/Home instead of the selected Panel User edit form in Main's hidden URL routing mode.

## Cause and solution
The v12.61 link used `#panel-user-password`. Main's hidden-route cookie validator rejects fragments, so canonical-root reload fell back to Home. The link now uses the allowed `?focus=password` query flag. The edit form reads that flag server-side and focuses the password input. The existing Show/Hide controls remain unchanged.

**This release does not reveal saved passwords**. Current credentials are only stored as one-way scrypt hashes and cannot be recovered. Adding future encrypted, recoverable passwords is a separate, security-sensitive design and has not been enabled by this release.

## Deployment and safety
- Main and bundled Node metadata `12.62`; Node runtime payload unchanged from v12.61.
- Installs only `app/templates/admin_users.html`, `app/templates/admin_user_form.html` and VERSION metadata.
- Has Node parity guard, backup and rollback.
- Only Main HTTP workers restart; no Main channel supervisor or Nginx restart.

Install on Main after release hash verification:

```bash
streamforge-update --force /root/streamforge-12.62.zip
```

Hard-refresh and open **Panel users → Change password**. The selected user's edit form should open and focus Password rather than Dashboard.
