# StreamForge v12.64 — Panel login source-IP lockout

## Security policy

Main Panel and Remote Node Panel logins now share a **source-IP** login
throttle instead of locking the Panel User account: after **5 invalid login
attempts from one IP within 15 minutes**, new Panel login attempts from that
same IP are rejected for **3 hours**. A valid Panel User on a *different IP*
can continue logging in. Unknown usernames and disabled accounts count too;
varying the username does not bypass the IP-level throttle. Successful login
clears pending failures for its IP. No Panel User's login is disabled globally.

Existing authenticated sessions, stream subscriber credentials, channel
supervisor, playback and Node Agent runtime are unaffected.

### Web management

Main Panel Super Admin: **Panel Users → Security · Panel Login · Blocked IPs**.
View IP address, failed attempts, block expiry, remaining seconds and Refresh.
The **Unblock** action requires the Super Admin's own password again,
HTTPS same-origin request, CSRF protection and audit logging. The separate
existing persistent throttle for incorrect unblock reauthentication stays in
place, as does password-vault reveal throttling.

### Real client IP and NAT safety

Main reverse proxy is trusted **only when its direct peer is loopback**. Use
the **rightmost** `X-Forwarded-For` hop set by the local Nginx reverse proxy
so an attacker cannot evade blocks by prepending arbitrary XFF values. Remote
Node forwards browser IP **inside authenticated encrypted Main/Node auth
envelope**, not an arbitrary browser-provided header. IPv4 and IPv6 are
validated and normalized. Invalid/missing IP or inaccessible guard storage
causes new login attempts to fail closed rather than silently disabling the
protection.

**Shared-IP trade-off:** If several admins are behind a NAT, CGNAT, VPN or
corporate proxy, five incorrect attempts from one client IP will temporarily
block Panel login for everyone sharing that IP. A CDN/reverse-proxy setup
must preserve the *real* browser IP at the rightmost trusted hop, otherwise
a CDN edge could be blocked. Verify production Nginx `real_ip` handling
and the expected request IP **before installing**. This is an application
Panel-login restriction, **not** a firewall rule; SSH and unrelated services
are not blocked.

### Storage and upgrade

The existing private 0600 Main-owned SQLite guard DB path (default
`/var/lib/streamforge/panel-login-guard.sqlite3`, or the configured
`STREAMFORGE_PANEL_LOGIN_GUARD_DB`) remains unchanged, with a new
`ip_failures` table. Prior v12.63 `login_failures` actor-ID rows remain
intact for rollback but are **ignored** by the new IP policy. This means any
pre-existing account locks no longer affect logins after upgrade.

Scoped updater `force_update_v1264.sh` accepts installed 12.63 or 12.64,
stages/verifies patch `app/main.py`, performs backup/rollback, validates
unchanged Node runtime file hashes and restarts only Main HTTP workers. It
does not restart Nginx, remote Nodes or channel supervisor. Node VERSION
is aligned to 12.64 metadata only. No change is made to optional v12.63
password vault behavior or key provisioning.

Install from an approved official v12.64 ZIP with:
```bash
streamforge-update --force /root/streamforge-12.64.zip
```
Do not use the updater until the code passes CI and the release is published.
