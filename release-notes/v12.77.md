# StreamForge v12.77 — Password policy and Node Panel headers

## What changed

1. **Panel passwords need at least 12 characters** and may not be the
   installation default (`ChangeMe123!`) or the `STREAMFORGE_ADMIN_PASSWORD`
   value from `/etc/streamforge.env`. The rule applies everywhere a Panel
   password is set: your own account, creating/editing Panel users, the
   password-reset popup, Node Panel password changes and
   `sudo streamforge resetuser`.

2. **A weak password must be changed at the next login.** Signing in with a
   default password or one shorter than 12 characters still works, but every
   Panel page then leads to **Account → Change password** until a compliant
   password is set. Existing users with 8–11 character passwords are asked to
   change them once. Playlists, Xtream, Web Player and streaming are not
   affected.

3. **Node Panel security headers.** The Remote Node Agent now sends
   `X-Content-Type-Options: nosniff` and
   `Referrer-Policy: strict-origin-when-cross-origin` on every response, and
   `X-Frame-Options: SAMEORIGIN` plus
   `Content-Security-Policy: frame-ancestors 'self'; base-uri 'self'; object-src 'none'`
   on Node Panel pages, matching the Main Panel since v12.76. Playlist/App and
   Web Player routes stay embeddable.

4. **Housekeeping.** Historical per-release tests skip themselves on other
   versions, stale expectations were updated, and two workflow steps that
   committed and pushed to long-merged branches were removed.

Not changed, by design: Node API tokens stay readable by Main (Main must
present them to Nodes; encrypting them with the secret key or a separate key
would break Nodes on key rotation or on restore to a new server), and Xtream
URLs keep their credentials (the Xtream protocol requires it; Nginx logs are
readable only by root/adm).

## Installation

Requires installed Main/bundled Node v12.76 (or v12.77 for a safe reinstall).
Update older servers to v12.76 first. Download and SHA256-check the official
release ZIP, then run:

```bash
streamforge-update --force /root/streamforge-12.77.zip
```

The scoped updater patches staged copies of the installed Main files with
`scripts/apply_v1277_security.py` (exact-text hunks; refuses if any anchor is
missing), replaces the **bundled** `node_agent/app.py` only after checking it
is the pinned v12.76 baseline, verifies every other Node runtime file
byte-for-byte, backs up to `/var/backups/streamforge/v1277-<timestamp>/` and
installs atomically. Backup, reinstall, baseline refusal and controlled
rollback are regression-tested. Only `streamforge` and `streamforge-public`
restart; the channel supervisor and live streams keep running.

**Running Remote Nodes are not upgraded automatically.** After installing
Main, open **Node Updates**, update every Node and confirm each reports
v12.77 so their Node Panels send the new headers.
