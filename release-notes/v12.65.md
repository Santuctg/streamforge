# StreamForge v12.65 — Show which server triggered a Panel IP block

Main Panel → **Panel Users → Security · Panel Login · Blocked IPs** now
includes a new **Triggered by server** column. It tells the Super Admin
which login handler received the **fifth incorrect password** that turned
the IP into a three-hour block. Examples: **Main Server** or
**Remote Node: CNBOX** (Node ID is retained as metadata).

The four previous failures could have occurred on other Main/Node panel
entrypoints. The 5/15-minute/3-hour policy, cross-Main/Node IP counter,
manual unblock CSRF + reauthentication, and other access controls remain
unchanged.

The guard uses the existing owner-only SQLite database and adds only a
`ip_block_origins` side table. It writes source kind, Main name or
authenticated Remote Node name and Node ID **atomically with the blocking
attempt**. It does **not** store passwords or new client secrets.
Successful login clears pending attempts; manual unblock removes the
related server metadata. Source labels are untrusted strings rendered
as text, never as HTML.

**Historical blocks:** The v12.64 DB did not record their trigger server.
Until they expire or are unblocked the UI correctly displays
**Unknown (blocked before tracking)**. This cannot be retroactively
reconstructed from the SQLite lockout row.

## Installation (Main only)

Upgrade from installed v12.64 using the official v12.65 archive after
PR/CI/release approval:
```bash
streamforge-update --force /root/streamforge-12.65.zip
```

The bounded updater stages existing Main `app/main.py`, applies the
v12.64 compatibility patch if needed, adds v12.65 source attribution,
compiles, verifies unchanged bundled Node runtime files, backs up the
affected files and restarts only `streamforge` and `streamforge-public`.
No remote Node, Nginx or stream supervisor restarts. Rollback restores
application files; the new unused side table can safely remain.

## Saved Panel passwords

The unrelated v12.64 vault flow remains as-is. Main → Panel Users →
**Show saved password** appears only after the Main vault Fernet key is
configured and that account's new/reset password was explicitly saved
with the vault checkbox. Existing one-way hashes cannot be revealed.
Self-service password changes currently invalidate any prior vaulted
secret; automatic escrow of Main/Node self-changes is not part of
this server-origin update.
