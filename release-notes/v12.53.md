# StreamForge v12.53

## Main waiting recovery

- Fixes Main Channels rows that stayed at `Waiting 0s` while their FFmpeg process was down between automatic recovery attempts.
- Persists `waiting_since` and `next_retry_at` so the Waiting duration survives failed retries and Main service restarts.
- Waiting duration resets only after the Main channel is genuinely Up; for HLS output this requires fresh HLS delivery, not merely a live FFmpeg PID.
- Keeps fast source-to-source failover inside a configured input cycle.
- After every configured input has failed, begins a new full input cycle every **60 seconds** instead of waiting the historical 30-minute dead-input interval.
- Manual Stop clears the Waiting episode. Manual Restart preserves it until delivery returns Up.
- Timer-only recovery channels are included in the dedicated Main supervisor runtime snapshot.
- The Channels page shows continuous Waiting duration and exposes the next retry countdown as `Retry in ...`.
- Preserves the v12.50 Main local-relay DB checkout fix and the v12.51 Node relay-health single-owner fix.

## Versions

- Main: `12.53`
- Bundled Remote Node Agent: `12.52` (unchanged; this is a Main-only release)

## Update

Download the v12.53 release ZIP and run:

```bash
streamforge-update --force /root/streamforge-12.53.zip
```

The updater restarts the Main channel supervisor and Main HTTP workers so the recovery policy is loaded. Remote Nodes are not modified or pushed by this Main-only update.
