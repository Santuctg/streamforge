# StreamForge v12.67 — Fix Remote Node self-service password change Permission denied

## Root cause and fix

A normal Panel User who clicks **Change password** on a Remote Node
could receive JSON `{"detail":"Permission denied"}`. The Node
`require_node_panel_user(request, "")` helper successfully authenticated
the user but then treated the intentionally empty permission key as a
missing role permission, inadvertently allowing only Super Admin wildcard
accounts to reach the personal password page.

The Node now checks RBAC only **when a named resource permission was
requested**. Personal Change password GET and POST still require a valid
live Main-authorized session. A disabled or revoked session is denied,
and if Main authentication is unavailable the request fails closed.
Other routes still require `channels.view`, `panel_users.edit` or their
specific permission as before. A low-privilege User can change **only
their own password**, not other Panel User credentials. Never grant
`panel_users.edit` just to fix this issue.

Existing v12.66 encrypted automatic managed-password retention still
applies on **updated** Remote Nodes: the form discloses storage and the
new password is encrypted in the Main-only vault. Main/Node IP login
lockouts remain unchanged (5 failures/15min, 3-hour IP block). Blocked
IPs Triggered by server remains available.

## Install and Remote Node update

From installed Main v12.66, use the official v12.67 archive after
CI/release approval:

```bash
streamforge-update --force /root/streamforge-12.67.zip
```

This bounded updater updates only the **bundled** Node
`node_agent/app.py` and Main/Node version metadata, backs up the
original and verifies known exact previous Git blob SHA and all
unchanged Node runtime file hashes. It restarts only Main HTTP services.
It **does not restart or upgrade running Remote Node services**.

To fix the affected `tslive.chitrobox.net` Remote Node, deploy the
v12.67 Node Agent through the existing Main **Node Updates** flow for
that Node and confirm the Node version. Remote Node password-change
will remain affected until its Node Agent code is upgraded.

## Regression tests

- Non-Super Admin with a valid Main-backed session can GET and POST
  their own password-change page (without `panel_users.edit`).
- Normal Channel permission checks still reject forbidden access.
- Missing/revoked sessions and disconnected Main fail closed.
- Installer tests cover upgrade, safe reinstall and rollback.
