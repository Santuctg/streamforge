# StreamForge v12.68 — Password Change popup and dark input styling

## Main Panel → Panel Users

The **Change password** buttons in both desktop tables and mobile cards now
open a modal on the current page, matching the existing **Show saved password**
interaction. The password-only form contains the chosen account's username,
New password, Confirm new password and Save/Cancel controls. No Edit User
page navigation, no accidental changes to role, username, active state or
Remote Node access. Passwords never enter URLs or HTML template attributes.

An authenticated edit-capable actor can submit a dedicated HTTPS same-origin,
session-bound CSRF-protected POST to reset only a visible, permitted Panel User
password. It retains the existing role hierarchy and requires
`panel_users.edit` (not `panel_users.password_reveal`). The new password's
scrypt hash and encrypted Main Vault entry are written together in one
database transaction. No credentials are logged or returned in responses,
and no plaintext is sent to Remote Nodes. Users with no edit permission
still cannot reset other Panel Users. An ordinary Panel User changing their
*own* password continues using the separate account-password page without
extra permissions.

The existing **Show saved password** reauthentication popup now has
explicit dark background, light text, focus outline, autofill colors and
`color-scheme:dark` for its password input. The new Change password popup
uses the same theme. This fixes the browser-native white input shown in
the screenshot and maintains contrast in dark mode.

The popup clears password input values when submitted or closed. After
a successful save the existing Panel Users page shows a success alert.

## Compatibility

Main-only UI/server change. v12.67 Remote Node Agent runtime is unchanged;
bundled Node version metadata aligns to 12.68. No changes to Nginx,
Channel Supervisor, stream routing, Panel Login IP block policy, or Remote
Node permission handling. Previous v12.66 auto-encrypted saved-password
policy remains enabled and disclosed to administrators in this reset dialog.

A Node's personal Change password form is not changed in v12.68.
The dedicated Node v12.67 personal-session fix still requires its
Remote Node to have been updated.

## Installation

Install v12.68 from an existing Main v12.67 using the official, verified
release package:

```bash
streamforge-update --force /root/streamforge-12.68.zip
```

Scoped updater backs up and stages Main `app/main.py`,
`app/panel_password_vault.py`, `app/templates/admin_users.html`,
and version metadata; validates Python syntax, CSRF patch, Node runtime file
parity and regression tests; performs controlled rollback on error. It
restarts only `streamforge` and `streamforge-public`, not Remote Nodes.
