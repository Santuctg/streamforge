# StreamForge v12.79 — Overview scripts reach the browser

## What changed

**Fixes v12.78 on upgraded servers.** Nginx serves the Panel's `/static/`
files from a published copy in `/var/cache/streamforge/main-static`, not from
`/opt/streamforge/app/static`. The v12.78 updater changed `app.js` and
`dashboard.js` in the application tree but did not refresh that copy, so
browsers kept receiving the v12.77 scripts: the values beside the chart
legends stayed empty, the first live refresh still waited five seconds and
the charts showed no "Loading…" note.

v12.79 republishes the installed static files into the Nginx cache, checks
every file byte for byte and bumps the version so browsers fetch the new
asset URLs. A release check now refuses any future updater that changes
`app/static` without refreshing this cache.

Fresh installs of v12.78 were not affected (the installer publishes the
cache). Nothing else changes: no application code, Node Agent, Nginx
configuration or database change.

## Installation

Requires installed Main v12.78 (or v12.79 for a safe reinstall). On v12.77
install v12.78 first. Download and SHA256-check the official release ZIP,
then run:

```bash
streamforge-update --force /root/streamforge-12.79.zip
```

The updater backs up `VERSION` files and the current static cache to
`/var/backups/streamforge/v1279-<timestamp>/`, refreshes the cache with
`scripts/sync_main_static_cache.py` (atomic replace with SHA256 checks),
verifies it matches `app/static`, and rolls back on failure. Only
`streamforge` and `streamforge-public` restart; Nginx, the channel supervisor
and live streams keep running. Reload the Overview page afterwards.

Remote Nodes need no update: the Node Agent is unchanged.
