# StreamForge v12.69 — Saved-password reveal text color + Remote Node password form cleanup

## Fixes

**Main → Panel Users → Show saved password:** The input previously received
dark styling only with HTML `type=password`. After clicking **Show**, the
existing JS switches that input to `type=text`; Chrome therefore applied
its default white background. The CSS now targets the stable attribute
`data-vault-secret-value` regardless of input type, including focus
and WebKit autofill, preserving dark background and readable light text.
No change to the reauthentication, 10-second hide, permissions, audit or
encrypted vault API.

**Remote Node → Change password:** The long **Managed password retention**
paragraph from the v12.66 Node page has been removed. A concise disclosure
is shown below the form fields: *New passwords are encrypted on Main and
can be viewed by authorized administrators.* This communicates the
administrator-recoverable policy without an oversized paragraph.
The confirm field spans the form width. Main's authenticated
`managed_password_notice=true` protocol stays unchanged.

## Deploying

The Main service and bundled Node Agent metadata update to **12.69**.
This is a scoped release from installed Main v12.68; use the official
archive after its CI/release check:

```bash
streamforge-update --force /root/streamforge-12.69.zip
```

The updater checks the installed Node Agent app.py against the **exact
v12.68 Git blob SHA**, hashes every other Node runtime file for parity,
then backs up/replaces only `node_agent/app.py`, Main
`app/templates/admin_users.html` and version metadata. It restarts
only Main HTTP services and rolls back on failure. Nginx, streaming
supervisor and running Remote Nodes remain untouched.

**Important:** The cleaned TS Live password form appears only after
**Main → Node Updates → TS Live** is upgraded to the new 12.69 Node Agent.
Installing Main alone cannot change a running remote web page. The
existing v12.67 personal password permission fix remains in Node Agent.
