# StreamForge v12.66 — Automatically retain newly changed managed Panel passwords

## Changes
**No Save Password checkbox.** Passwords newly created/reset under
**Main Panel → Panel Users** are encrypted in the separate Main-only Fernet
vault within the same transaction as the authentication scrypt hash. Password
changes through **Main Panel → Change password** are also retained.

On **updated v12.66 Remote Nodes**, the self-service Change password form
visibly discloses that administrator-recoverable credentials will be saved.
The Node sends `managed_password_notice=true` inside the already encrypted
and authenticated live-auth envelope to Main, and Main automatically stores
the new credential with the freshly updated hash. Nodes still on v12.65 or
earlier do **not** silently escrow self-chosen passwords: they retain the
previous behavior of invalidating any stale vault copy. Upgrade each Remote
Node to v12.66 through the existing Node Updates flow to enable this on
that Node. The Main update itself does not restart Remote Node services.

No old one-way hashes can be recovered. Re-authenticated viewing still uses
the existing `panel_users.password_reveal` permission, target-role ceiling,
audit trail, HTTPS, CSRF, no-store response and 10-second auto-hide. No
plaintext password is logged or synchronized as plaintext to Nodes.

### Managed credential disclosure and access
All Main account password forms explicitly notify users/admins that password
retention is a managed-account policy. Updated Node change-password forms
display the same notice. Access to the encrypted key and stored credentials
must be limited: users should understand administrator recovery access.
This significantly increases the impact of a compromise of the Main database
*and* its separate encryption key.

The encryption key `STREAMFORGE_PANEL_PASSWORD_VAULT_KEY` must already be
configured for the Main `streamforge` service; missing/invalid keys cause
Main-managed create and password changes (and updated Node password changes)
to fail instead of silently retaining only a hash. Existing user logins are
not gated by the vault key.

### Installation
Install on Main (supported current version 12.64 or 12.65):
```bash
streamforge-update --force /root/streamforge-12.66.zip
```
Main updater stages 12.64 → 12.65 → 12.66 bounded patches, tests Python
syntax without writing bytecode, backs up changed Main/Node source,
verifies all unchanged Node runtime bytes and exact previous Node app.py
baseline, and restarts only Main HTTP services. The bundled Node v12.66
app.py can then be rolled out to Remote Nodes through Node Updates.

`v12.65`'s Blocked IPs **Triggered by server** feature and the v12.64
5-failures/15-minute/3-hour IP-only lock policy remain intact.

Rollback copies application files back; never delete or regenerate the
persistent encryption key. Preserve a secure separate key backup.
