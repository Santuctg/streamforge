StreamForge v13.51 — Main Web Player 500 hotfix

- Fixed the Main Web Player 500 error: `app/templates/web_player.html` contained a stray Jinja `{% endif %}` left behind when the v13.48 light-theme block moved. Jinja rejected the whole template, so every Playlist/Web Player alias — for example `https://server.chitrobox.net/123` — returned "Internal Server Error" even though the Main panel itself was healthy.
- `/123`, `/web-player` and the other Playlist/App aliases render the channel list and login screen again after the update.
- Added `scripts/verify_template_syntax.py`: it parses every template under `app/templates/` and renders the Web Player in both signed-out and signed-in states. The release workflow runs it before building the update ZIP, and the v13.51 updater refuses to install a package whose templates do not compile.
- The v13.50 name-card theme switch, the visible light-theme checkbox and the v13.49 tokenised light palette are unchanged.
- Main-only change: Node Agent runtime bytes are unchanged and Remote Nodes do not need an update.

```bash
sudo streamforge-update --force /root/streamforge-13.51.zip
```
