StreamForge v13.54 — self-hosted HLS.js fix and light dropdown popups

- Fixed the Main Web Player watch screen failing on freshly installed releases: the self-hosted HLS.js was requested from the `{{ prefix }}`-prefixed `/123/static/...` URL, which Nginx silently drops behind playlist aliases (origin 404 -> connection drop), so the cache-busted request died on every new version and playback depended on a third-party CDN (often unreachable). The watch screen now loads HLS.js from the Nginx `/static/` cache at host root — the same path every other page asset already uses — with the CDN fallbacks unchanged.
- Fixed the light theme dropdowns: the dark stylesheets force `color-scheme:dark` on every `<select>`, so the native option list stayed dark after switching to light on both Main and Node. Light themes now force `color-scheme:light` on selects and give the options readable light colours.
- Main-side changes ship with the staged updater guard: the release refuses a package whose watch screen still uses the prefixed HLS.js path, whose light theme lost the select overrides, or whose templates do not compile. The Node Agent keeps the v13.53 device theme; its light select override is carried.
- Remote Nodes receive the updated Node Agent from Main automatically.

```bash
sudo streamforge-update --force /root/streamforge-13.54.zip
```
