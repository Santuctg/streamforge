# StreamForge v12.50

## Main relay DB checkout release

- Adds `STREAMFORGE_LOCAL_RELAY_DB_CLOSE_V1250` to the Main local-relay playlist and segment handlers.
- Releases the SQLAlchemy request session immediately after relay authorization, before filesystem/HLS work, preventing relay fallback traffic from holding Public worker QueuePool connections while media availability is checked.
- Keeps the existing relay recovery behavior intact: transient availability remains retryable, while converged `restarting + process down + no recent HLS` state continues to return `409`.
- Includes an update-safe verifier and patcher so the release workflow carries the source-level fix into the `v12.50` tag and later release archives cannot silently regress it.
- This is a Main-server hotfix. The Remote Node Agent is not upgraded by this release; Node update work follows separately.

## Production validation

- Post-hotfix relay fallback traffic did not reproduce the prior SQLAlchemy QueuePool timeout.
- Observed `502` responses were confined to the brief `streamforge-public` restart window.
- The Main relay `409` recovery path was verified with the internal Nginx fallback marker and returned `restarting / FFmpeg down / no recent HLS` as expected.

## Update

```bash
streamforge-update --force /root/streamforge-12.50.zip
```

After update, verify:

```bash
cat /opt/streamforge/VERSION
grep -n 'STREAMFORGE_LOCAL_RELAY_DB_CLOSE_V1250' /opt/streamforge/app/main.py
systemctl is-active streamforge streamforge-public streamforge-channel-supervisor
```
