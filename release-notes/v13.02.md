StreamForge v13.02 — Notification Center for Stream Users and Node Server owners

## What's new

- **Notification Center** at *Notifications* in the Panel sidebar: SMTP delivery settings with an encrypted password, a send-test control, automatic expiry reminder scheduling, separate Stream User and Node Server templates, manual campaigns, and a persistent delivery history with retry/resend.
- **Contacts on both recipient types**: Stream Users gained `contact_email` + an email-notification toggle; Node Servers gained `contact_name`, `contact_email` + an email-notification toggle. Both forms expose the new fields.
- **Automatic expiry reminders** for Stream Users *and* Node Server owners at configurable day offsets (default 30/14/7/3/1 and expiry day). Reminders are deduplicated per recipient, per expiry and per event, so a restart never double-sends. Renewing or changing an expiry cancels queued reminders for the old date.
- **Safe delivery queue**: every message is persisted, retried up to three times with backoff, and logged with its error; failed items can be retried or resent from the UI. New permissions `notifications.view`, `notifications.send` and `notifications.manage` gate the page; Super Admins get them through the wildcard.
- Hardened the Main Updates confirmation so it no longer interpolates release data into an inline `confirm()` string.
- New bounded updater `scripts/force_update_v1302.sh`; both VERSION files bumped to 13.02. Node Agent runtime bytes are unchanged, so Remote Nodes do not require an update.

## Scope and safety

- Email delivery stays **off** until an operator configures SMTP and enables it; no message is sent without SMTP configured, and the automatic-reminder switch is separate from the master delivery switch.
- SMTP credentials are stored encrypted and are never rendered back into the page.
- The web worker only queues work; the notification worker sends from the control worker and never executes privileged commands.

Requires installed Main **v13.01**. Node Agent runtime bytes are unchanged, so Remote Nodes do not require an update.

```bash
sudo streamforge-update --force /root/streamforge-13.02.zip
```
