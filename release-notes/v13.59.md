StreamForge v13.59 — Node HLS override passes Main access policy

- Fixed the "Main Panel HTTP 403: Access denied" error on the Node panel when a panel user with the Edit channels permission changed the HLS segment of a shared channel: Main's browser IP/ASN panel whitelist rejected the Node's own address because the `/api/v1/node-channel-hls-segment/` control endpoint was missing from the machine-to-machine policy bypass. The heartbeat, node-control, back-sync and live-auth endpoints already had that exemption.
- Main now exempts the HLS segment override endpoint the same way: it stays X-Node-Token authenticated, so only genuine Nodes can use it, while the browser IP/ASN rules keep protecting the human-facing Panel.
- The Node Agent bytes are unchanged and Remote Nodes do not need a new agent. The v13.54-v13.58 fixes are carried unchanged.

sudo streamforge-update --force /root/streamforge-13.59.zip
